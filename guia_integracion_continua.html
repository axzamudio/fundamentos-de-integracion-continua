Fundamentos de Integración Continua

El Paradigma Ágil según Martin Fowler (2006)

"Típicamente cada persona integra al menos una vez al día, generando varias versiones por día. Cada versión ejecutable es verificada por un sistema automático de integración y pruebas para detectar errores de integración lo más rápido posible."

En el desarrollo tradicional, los equipos trabajaban de forma aislada durante semanas o meses, lo que provocaba el temido "Integration Hell" (infierno de la integración) al final de los ciclos. La Integración Continua (CI) reemplaza este aislamiento mediante integraciones atómicas y retroalimentación constante.

⚖️ Comparativa: Enfoque Tradicional vs. Integración Continua

Criterio Método Tradicional Integración Continua (CI)
Velocidad de Entrega Lenta (entregas semestrales o anuales) Ágil (múltiples builds por día)
Costos Operativos Elevados por resolución tardía de fallos Optimizados mediante automatización
Margen de Error Altamente susceptible al error humano Minimizado con pruebas y suites de CI
Calidad del Software Media / Baja por falta de visibilidad Alta y monitoreada constantemente
Comunicación y Feedback Reunión sólo al inicio y al final Historial público y trazabilidad activa

🌿 Estrategia de Flujo de Ramas (Git Flow)

Master / Main

Código de producción 100% estable, listo para despliegues oficiales a usuarios.

Develop

Rama integradora de trabajo activo donde converge el desarrollo antes de estabilizar.

Feature

Ramas individuales por cada nueva funcionalidad o tarea asignada al desarrollador.

Release

Fase de congelamiento para pulir y realizar pruebas de versión antes de liberar.

Hotfix

Parches críticos e inmediatos que surgen directamente sobre el ambiente de producción.

Arquitectura de Servidores CI

Haz clic sobre cualquiera de los nodos del diagrama para inspeccionar su función técnica y responsabilidad dentro del ecosistema de Integración Continua (según la Figura 1 de la lectura oficial).

Servidor de Integración Continua (Core)

Es el cerebro orquestador del sistema (ej. Jenkins o Travis CI). Escucha los Webhooks del repositorio central tras cada Push o Pull Request, clona el código, dispara los pipelines de compilación, invoca el análisis estático y ejecuta las pruebas automatizadas.

🐳 Máquinas Virtuales (VM) vs. Contenedores Docker

🖥️ Máquina Virtual (Hipervisor)

  • Incluye un Sistema Operativo invitado (Guest OS) completo con kernel propio.
  • Consumo intensivo de recursos de CPU, memoria RAM y almacenamiento.
  • Arranque lento que tarda varios minutos.
  • Aislamiento estricto a nivel de hardware virtualizado.

📦 Contenedores Docker

  • Comparten el Kernel del Sistema Operativo anfitrión (Host OS).
  • Ligereza extrema: imágenes de pocos megabytes y consumo mínimo de RAM.
  • Arranque instantáneo en cuestión de milisegundos.
  • Garantiza paridad total entre desarrollo, pruebas y producción.

Ecosistema de Herramientas

GitHub & Marketplace

VCS / Colaboración

Plataforma central basada en Git para control de versiones, Pull Requests, revisiones de pares y gestión de incidencias. Su Marketplace permite integrar bots, linters y servicios de CI/CD en un clic.

Rol en el curso: Alojamiento del proyecto y disparador de eventos vía webhooks.

Travis CI

SaaS CI

Servicio de integración continua en la nube sincronizado de forma nativa con GitHub. Automatiza la compilación y prueba de aplicaciones mediante la configuración de directivas en el archivo .travis.yml.

Rol en el curso: Pipeline automatizado de validación con cada commit.

Jenkins

Self-Hosted CI

Servidor de automatización Open Source líder en la industria. Permite definir pipelines mediante Jenkinsfile y extender sus capacidades con miles de plugins para cualquier lenguaje y nube.

Rol en el curso: Comprensión de arquitecturas de servidor CI locales y empresariales.

Docker

Contenedores

Herramienta de contenedores que empaqueta una aplicación y todas sus dependencias exactas en un contenedor estandarizado, asegurando que el software se ejecute sin discrepancias en cualquier servidor.

Rol en el curso: Entornos reproducibles y aislamiento de pruebas en CI.

Zenhub

Gestión Ágil

Herramienta de gestión de proyectos ágiles integrada nativamente dentro de la interfaz de GitHub. Proporciona tableros Kanban, epics, estimaciones de historia y métricas de velocidad sin salir de los repositorios.

Rol en el curso: Trazabilidad ágil de tareas grupales y sprints.

Sentry

Monitoreo / APM

Plataforma para el monitoreo de fallos y rendimiento en tiempo real. Rastrea excepciones no controladas, muestra el stack trace detallado del código afectado y envía alertas inmediatas a los desarrolladores.

Rol en el curso: Monitoreo proactivo en entornos de prueba y producción.

Codecov (Code Coverage)

Calidad de Código

Herramienta de métricas que se conecta a los pipelines de CI para medir y auditar el porcentaje de código cubierto por pruebas automatizadas, bloqueando Pull Requests que disminuyan la cobertura del proyecto.

Rol en el curso: Aseguramiento de calidad y umbrales mínimos de testing.

Guía de Instalación GitHub Desktop

A continuación se presenta el procedimiento paso a paso para la descarga, instalación y configuración del cliente GitHub Desktop según la documentación oficial de la asignatura:

  1. 1. Ubicar en Google "github desktop"
  2. 2. Seleccionar la opción de descarga para Windows
  3. 3. Validar la descarga en la carpeta del equipo
  4. 4. Realizar el proceso de instalación
  5. 5. Seleccionar la opción de "Sign in to GitHub.com"
  6. 6. Crear una cuenta de usuario si no la tenemos
  7. 7. En la instalación autorizar Desktop
  8. 8. Ya podemos ingresar
  9. 9. Creamos un nuevo repositorio local
  10. 10. Se toma una carpeta que tenga uno en el computador y que quiera compartir
  11. 11. Se escribe el mismo nombre de la carpeta que se quiere compartir
  12. 12. Se crea el proyecto seleccionando la opción "initialize this repository with a README"; esto permite crear automáticamente un archivo README para documentar el proyecto
  13. 13. Se publica el repositorio
  14. 14. Se visualizan los proyectos creados en la plataforma
  15. 15. Entre las opciones en GitHub encontramos: "Open in Visual Studio Code" para abrir el proyecto y editar el código, "Show in Explorer" para abrir la carpeta del proyecto en el explorador de archivos de Windows, y "View on GitHub" para abrir el repositorio en la página web en línea

Entregas del Proyecto Grupal

Semana 3 Entrega 1

Configuración del Entorno y Repositorio

Creación del repositorio público central en GitHub, vinculación del equipo de trabajo, establecimiento de directivas README.md, estructura base del software y tableros de control en Zenhub.

Objetivo: Repositorio base y asignación inicial.
Semana 5 Entrega 2

Pipeline de CI y Pruebas Unitarias

Integración de Travis CI o Jenkins con el repositorio. Ejecución automatizada de pruebas unitarias con cada Pull Request, reporte de métricas de cobertura y empaquetamiento en contenedores Docker.

Objetivo: Automatización de builds y testing.
Semanas 7 y 8 Entrega 3

Despliegue Continuo, Monitoreo y Sustentación

Despliegue automatizado en servidor staging/producción, integración del monitoreo de errores con Sentry, entrega de informe final y sustentación técnica del flujo grupal de trabajo.

Objetivo: Ciclo CI/CD completo y defensa.
